# 变长、变序的到达回放：C500 原生 vLLM‑MetaX

不再把 20 条一起发的固定形状成绩当作所有负载表现。本轮是模拟流量（不是线上采样）：3 个固定种子（31/47/89），每条 32 请求、39,808 输入、4,672 固定输出；输入 96–3072、输出 32–384 token。每条 trace 的形状组合数量都相同，重排次序、重采样到达间隔；由低到达率开始，中段突发，随后变缓，所有请求仍按各自预定时间进入实验，不等另一个请求完成。保持引擎最多运行 16 条，排队是结果，不是人为删掉。

每个配置热身后，逐个重放**同一个文件**（相同 token IDs、时刻、输出数）并保留每次结果。两种 K1 总预算在同一进程中交错；动态 K 和长请求切片各用独立进程。下表是三个 trace 各自观测值的中位，不是逐请求合并 P95，不是发布准入。TTFT 按预定到达时间起算，进程内同步提交的延迟也计入；另行记录实际 submit lag，不外推为 HTTP 延迟。

| 配置 | 输出 tok/s | p95 首 token（s） | p95 整条（s） | 短 / 长请求 p95 首 token（s） |
|---|---:|---:|---:|---:|
| **固定 K1 / 总预算 4096** | **131.57** | **10.89** | **28.91** | **10.89 / 11.14** |
| 固定 K1 / 总预算 2048 | 129.48 | 11.48 | 29.02 | 11.48 / 11.98 |
| 固定 K1 / 总预算 4096 / 长请求每步最多 1024 | 130.25 | 11.45 | 29.58 | 11.45 / 11.61 |
| 动态 K（1–4 条 K2，5–16 条 K1）/ 总预算 4096 | 94.82 | 18.75 | 40.38 | 18.75 / 19.08 |

短请求是输入不超过 128，长请求是输入至少 2048。固定 K1/4096 的三条轨迹是 124.75 / 131.57 / 137.58 tok/s；仅变更顺序和到达间隔就有约 10% 极差。其 p95 首次调度等待中位为 10.33 s，峰值等待队列中位 13 条，不应该只看核耗时。两种切小预算方案都没有改善短请求或总体 p95 首 token。

## 动态 K 与 Graph

预热审计对每个实际调用的 `CUDAGraph.replay` 计数：固定 K1/4096 **22** 次，动态 K **0** 次。动态 K 的调度输出实际出现 K1 与 K2（审计 37 / 6 个 step）；非仅写入配置。正式计时不插入 Graph 回放钩子。安装的 runner 以配置的统一 query 长度判定 FULL_DECODE_ONLY 是否适用，变长 K 与观察到的回放缺失相符；本轮没有单独隔离其他开销，不把回退全部归因于某一行代码。不推荐当前构建用这组动态 K 默认替换固定 K1。

## 复现入口

- `generate_open_loop.py --model --out` 一次生成 trace JSON；所有模式复用同一份，不在每个计时运行里重新采样。
- 按 [隔离 / 锁 / 截止](../../docs/REPRODUCING.md) 启动独立的 `replay_open_loop.py --model --trace --out --mode k1|dynamic|longcap`；`k1` 进程对总预算 4096/2048 交错，`longcap` 使用原生 `long_prefill_token_threshold=1024`、总预算仍 4096。质量可另给 `--quality`，其输入用前一页的同一公开题 fixture。
- 原始运行目录含 `trace.json`、`dev/`（仅用于数学答案核验），以及 `k1/`、`dynamic/` 和 `longcap/`。用 `summarize_open_loop.py <RUN_DIR>` 汇总。保留预热和计时两类原始文件。
- 不把上一轮 187.74 tok/s 或作者固定批成绩直接和这组做性能倍数。我们没有用这组时间戳重测 SpecPilot，也没有真实 HTTP 接入、线上到达日志或长时间持续服务可靠性结论。

## 自然 EOS 质量检查

同一套 20 题，独立分批到达；生成上限 2048，允许 EOS。自然档中生成量不同，不能根据 tok/s 宣称等工作量加速。动态 K 在固定工作量档已经明显回退，未再跑质量。

| K1 配置 | 墙钟 s / 输出 token | 最终数学 | HumanEval | MBPP |
|---|---:|---:|---:|---:|
| 4096 | 97.64 / 18,393 | 6/8 | 4/4 | 2/4 |
| 2048 | 100.49 / 18,287 | 6/8 | 4/4 | 1/4 |
| 4096 / 长切片 1024 | 100.81 / 19,323 | 6/8 | 4/4 | 1/4 |

因此保留 **固定 K1 / 4096** 作为后续基线，不改变默认服务。三路进程正常退出；GPU 返回空闲，未见设备非法访问、KV preemption 或新增 cgroup OOM。只做了小样本输出质量筛选，没有长文本盲评、全词表 logits 或四类缓存独立验收。
